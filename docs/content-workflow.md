# 内容工作流

## 一条建议从提出到发布

1. **发现问题**：从读者 issue、社交平台高频问题（Tier 3，只作线索）中找到“大家真的在问什么”。
2. **查重**：先在 `data/entries/` 和网站搜索；相近的条目应合并或补充，而不是新建。
3. **找来源**：按 [来源政策](source-policy.md) 找 Tier 1 / 2 来源；先登记到 `data/sources/sources.yaml`，并运行 `npm run verify:sources`。
4. **读来源**：至少读到摘要或网页正文；在条目的 `sources[].supports` 中用自己的话写出**这条来源具体支持了什么**，并标注 `locator`。
5. **写条目**：一句话结论 → 建议 → 为什么 → 怎么做 → 例外 → 警示信号。不确定的地方写进 `evidence.gaps`，标 `TODO / NEED REVIEW / UNKNOWN`，**不要在正文里写没有来源支持的说法**。
6. **评分**：按 [评分方法](scoring-methodology.md) 的锚点填分，并在 `scores.rationale` 写理由。
7. **自检**：`npm run check`。
8. **PR 审核**：高风险条目需要第二人审核；证据等级上调必须写进 CHANGELOG。

## AI 可以做什么，不可以做什么

| 允许 | 不允许 |
|---|---|
| 总结论文、整理资料、生成初稿 | 无来源生成医疗事实 |
| 分类、提取元数据、检测重复 | 编造论文、DOI、组织指南 |
| 改善文字 | 自动提升证据等级 |
| 提议证据等级（附理由） | 把搜索摘要当成论文结论 |

用 AI 研究的条目标 `review_status: ai_researched`。**AI 研究 ≠ 兽医审核。**

## 第一轮的经验（2026-11）

- 凭记忆写出的一个 DOI（Rumbeiha 2004 百合研究）指向了另一篇论文，Crossref 核对时才发现。**所有 DOI 都必须经脚本核对。**
- 一些广为人知的兽医常识（例如“胖猫突然断食可能引发肝脂沉积症”）在第一轮没有读到支持来源，所以没有写进正文，只记在 `gaps` 里。宁可少写。
- 指南全文常常读不到：如实标注 `read_level: abstract`，没读到的具体数字（体检频率、疫苗间隔）不写死。

## 查重的局限

`npm run dedupe` 用“同义词归一 + 字符二元组 TF-IDF 余弦 + 标签/来源重合度”估计相似度：

- 能抓住：同一件事换了说法（“每天换水 / 保持饮水新鲜”）、同义口语（“尿不出来 / 尿闭”）。
- 抓不住：完全不同措辞、不共享同义词的同一概念。
- 所以人工审核仍然必要；同义词表是提高查重和搜索质量的主要手段。
- 规划中：加入可选的本地 embedding 相似度，作为额外信号而不是替代。

## 冲突处理

可靠来源意见不同时，设置 `evidence.conflict: true`，在 `conflict_notes` 中列出每种观点及其来源，并写出“当前更合理的解释和适用条件”。不要偷偷选一个。

## 复核

`npm run stale` 列出超过复核周期的条目。复核时重新读来源，确认是否有新版指南；**脚本永不自动修改医学结论**。
